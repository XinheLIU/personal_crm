# 沃德利地图 (Wardley Map)

创始人：[[Simon Wardley]]

## Core Principle
**「值得独一无二的，自己做；可以平平无奇的，外包给世界。」**

## Map Structure
直角坐标系：
- **纵轴**：价值链可见度，从底层支撑设施到最终用户
- **横轴**：演进阶段（从左到右不可逆）：
  1. 创生 (Genesis) — 极新、风险大
  2. 定制 (Custom-built) — 已有价值但未标准化
  3. 产品/租赁 (Product/Rental) — 功能已定义，可直接买
  4. 商品/公共设施 (Commodity/Utility) — 高度标准化、极便宜

**一切模块都在不断向右移动。**

## 战略动作

### 下注方向
- **主战场**：中左区域（创生/定制 + 靠近用户）→ 建立 Alpha 优势的源头
- **坚决外包**：右下角（成熟标准化 + 离用户远）→ 云服务、支付、CRM

### 产品化迁移
- 高手从一次性项目中「偷出」可复制部分
- 把左侧优势主动推动到右侧的产品/服务，规模化放大利润

## 三个常见误区
| 误区 | 表现 |
|------|------|
| 错把控制感当竞争力 | 自建云、自研登录/支付/CRM，只为心理安全感 |
| 错把技术难度当战略价值 | 自己写支付网关很酷，却不是价值链关键节点 |
| 用右侧伪努力逃避左侧真困难 | 折腾 AI 流程、重复造轮子，在用户看不出的事上拼命 |

## Classic Case: UK GDS
要求各部门画地图，发现大量本应商品化的底层（服务器机架、支付网关）被重复定制建设 118 次→ 砍掉后节省数十亿英镑。

## 个人应用
- 用户意识：先回答「谁在为我买单？」
- 左右意识：Python、提示词模板等已商品化，只是入场门票
- 应该重心放左：垂直行业深度理解、数据到决策的叙事能力

**「凡是能便宜买到的，就不必成为你；凡是能真正定义你是谁的，绝不能外包。」**
