## 3. 演讲 4 点（这是项目期间最 sellable 的方法论提炼）

> 在某次会议上的发言整理，提炼了 AI 转型的 4 个核心要素。可独立复用。

### 3.1 场景需求
- 这波 AI 变革与之前 IT、数字化**最大的不同**：少数场景产生了重大影响，**并非均匀分布**
- 比如 **5% 的场景能创造 90% 的价值** — 这其实就是**场景聚焦**
- 真正能体现 **AI 原生优势**的场景，是关键
- 规划重点：**识别最有潜力的场景，且一个都不能遗漏**
- 这种场景聚焦**很像 VC 投资** — 企业在内部寻找高潜力"投资点"
- 这是与过去 IT 数字化赋能**最大的区别**

### 3.2 激活数据
- 无论是理赔还是寿险业务，**核心在于如何激活数据**
- 把业务中的**文本、语音**等可用数据利用起来
- 有些数据可能尚未收集但可以着手：
  - **活动数据**：线下收集更可控
  - **营销员社交数据**：较难获取（与团长在 [06](06-stakeholders-interviews.md#数据问题) 中提的"销售人员控制力弱"对应）
- **激活数据**是**场景聚焦后的关键路径**
- 需要**务实对待优先级** + 内部数据整合

### 3.3 智能原生
- 在场景聚焦和数据激活后，**从智能体原生维度充分释放潜力**
- 例：整合客户多模态数据（问答、语音、视频等）
- 构建具备**产品化运营能力**的智能客服中心
- 以此**攻克高价值场景**
- 必须抓住智能体验的：
  - **动态迭代**
  - **个性记忆**
  - **无限感知**

### 3.4 在生产环境中磨练
- 痛点往往**在实战中暴露**
- 但早期也要注意**人才培养**
- 若将人才分散到各领域，可能会**缺乏思维碰撞**
- **结合实战 + 虚拟交流**：
  - 案例分享
  - 方法论研讨
  - 像冰冰提到的"**以客户旅程为中心，以智能体为抓手，数据突破、智能协同**"的理念
- 快速培养**人才浓度**

### 3.5 总结：核心要素 = 场景 + 数据 + 智能体
- 今天**解剖麻雀式**的分析，就是**聚焦最能"挖富矿"的场景**
- **再倒推**技术架构和数据基建
- 激活数据、打造智能原生能力、凝聚人才 — 都需要快速识别、培养和聚集
- **人才稀缺**，应将核心资源**聚焦在能产出业务结果、形成正向牵引的场景上**
- 避免**"撒胡椒面"**
- **整体逻辑**：场景需求 → 激活数据 → 智能原生 → 人才沉淀

## 4. 阳光汇报反思

### 4.1 孙老师思路
- 思路**确实有亮点**
- 但 **ego 很强的人 sell 的时候也有缺点**：**看不到别人的诉求**

### 4.2 技术落地 vs 愿景的 balance
- **很多东西方向很对**
- 还是马云说的：**一流的执行 / 在胜利的组织什么都不是问题**
- 一个团队**不应该不断跳票**

> 这一段是项目最尖锐的元反思 — sell 是技术、执行也是技术

## 6. 大企业的本质 — 信息流问题

> 这一节是阳光项目带出的最深的元洞察。

- **大企业核心是信息流的问题**
- **为什么张一鸣强调透明**
- 其实**每个人都基于自己的利益说话**
- 上面的人和**土皇帝一样**，根本看不清真相了
- **打造企业这个 product 就是干这个**

## 与 Apple-Project 元学习的对照

放在两个项目都跑完后看，方法论之间互为补充：

| 主题 | Apple-Project | 阳光保险项目 |
|---|---|---|
| 项目重做的元 framework | "如果重做" 五项积累 | "演讲 4 点"（场景 / 数据 / 智能 / 实战）|
| 估值 / 资本叙事 | PE Ratio 两大支柱 | "战略想象空间大"在阳光是 IT 转型 5 缺陷 + 项目→平台 |
| Make-a-deal | 用资源 / 利益 / 诉求解构 | 大企业信息流 + 张一鸣透明 |
| 组织观察 | 阿里 P7→P10 阶梯 | 阳光大灯塔 vs 替代率 + 业务和技术的张力 |
| 个人定位 | 减少对合伙人依赖 | 所有 agent 的课定位明白 |

→ **元结论**：动势两个标杆案例（Apple + 阳光）都把"生意视角 + 组织视角 + 技术视角"三者串了起来。下一步要做的是**沉淀成方法论 hub**（用户暂未要求，按 messy-to-mece skill 的 Phase 2 决定保留在子文件夹内 — 等多项目积累后再做横向抽取）。
