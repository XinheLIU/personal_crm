# 05 — 企业级 IT 转型 — 5 大缺陷 & 项目→平台 升级

> Last updated: 2026/05/05

## TL;DR

阳光当前的 AI / 数智化推进**模式 = 战术级、分散、并行的项目模式**，导致**战略失焦 + 数据割裂 + 技术混乱**。具体暴露 **5 大致命缺陷**：① 业务能力重复建设、② 价值衡量与迭代闭环缺失、③ 用户体验割裂、④ 企业知识资产未形成合力、⑤ 数据治理与主数据缺失。**转型建议**：从"项目"升级为"平台"的战略级顶层设计 — 成立**跨部门委员会（AI 战略委员会 + AI CoE）**+ **启动三大基础平台（AI Agent 中间件 / 企业级数据平台 / 企业知识大脑）**+ **重新评估现有 18 个项目**为驱动平台建设的"典型场景"，选 2-3 个试点。**关键技术架构**：分层解耦（模型层 / 能力层 / 编排层 / 应用层）+ 统一 Agent 中间件 + 流式数据处理。**这是项目最核心的可 sell 输出**。

---

## 当前痛点：战术级项目模式的致命缺陷

> 当前分散、并行的项目模式缺乏整体规划，导致战略失焦、数据割裂和技术混乱。

### 缺陷 1：业务能力重复建设
- **问题**：集团内通用的横向业务能力（如客户对话、管理洞察）被拆分到不同项目中独立实现 → 资源分散和浪费
- **举例**：智能客服、销售机器人、理赔服务都各自研发对话引擎，**而非共用一个统一的"客户意图理解与对话中心"**

### 缺陷 2：价值衡量与迭代闭环缺失
- **问题**：项目目标宏大但缺乏统一、量化的评估体系；机器人上线后无法通过真实世界的反馈持续进化
- **举例**：项目指标多为覆盖率和功能实现（如"精准率达 80%"）— 但**缺乏明确定义和衡量标准**；多数项目未规划 **A/B 测试和人工反馈（RLHF）机制** → 模型无法持续优化

### 缺陷 3：用户体验割裂
- **问题**：同一用户需在不同机器人之间切换，且交互方式不统一 → 增加学习成本和操作难度
- **举例**：一线销售需同时使用"销售机器人"和"智能客服"，但**交互逻辑不同 → 易出错**

### 缺陷 4：企业知识资产未形成合力
- **问题**：多个项目各自建立独立的知识库 → 知识无法共享、重复录入、更新不同步
- **举例**：智能写作、智能客服和销售机器人各自维护独立的保险知识库 → **无法形成一个统一的"企业知识大脑"**

### 缺陷 5：数据治理与主数据缺失
- **问题**：项目低估了数据治理的复杂性；在缺乏统一**主数据管理（MDM）**的情况下，每个机器人都会成为新的数据孤岛 → 加剧数据混乱
- **举例**：队伍成长机器人需要来自人力、风控、纪检的数据，但各系统数据未打通 → 模型训练数据不全 + 画像失真

## 转型建议：从"项目"到"平台"的战略升级

> 为了解决上述问题，建议**立即暂停分散的项目启动**，转向以"平台"为核心的战略级顶层设计。

### 核心行动路线图

#### 1. 成立跨部门委员会
- **AI 战略委员会**
- **AI CoE**（Center of Excellence）
- 负责：横向规划 / 治理 / 标准制定

#### 2. 启动三大基础平台
- **AI Agent 中间件平台**
- **企业级数据平台**
- **企业知识大脑**

#### 3. 重新评估项目
- 现有 **18 个项目**重新定位为**驱动平台建设的"典型场景"**
- 选择 **2-3 个作为试点**
- 在构建平台的同时验证业务价值
- 实现**"平台与应用"同步迭代**

## 关键技术架构建议

### 分层解耦的平台式架构（4 层）
**而非"烟囱式"的独立开发模式**：

| 层 | 作用 |
|---|---|
| **模型层** | 通用 / 专业 / 蒸馏后的小模型 |
| **能力层** | 客户对话、知识检索、决策推理等可复用能力 |
| **编排层** | 工作流 / 多智能体协作 / 状态管理 |
| **应用层** | 各类机器人 / 业务系统嵌入 |

→ **实现技术复用 + 维护成本降低**

### 统一 Agent 中间件平台
应构建一个统一的 Agent 中间件，提供：
- **上下文管理**
- **安全工具调用**
- **状态监控**
- 用于管理 Agent 的**生命周期 + 协作**

### 数据时效性
- 架构设计中应考虑**流式数据处理**和**实时计算**
- 满足部分机器人对**数据实时性**的高要求
