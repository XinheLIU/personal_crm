# Value Capture, Rent, and Alpha

> Last updated: 2026-05-30

## Output style

- Default to short Markdown: 2-4 sections, one compact table when useful, 3-5 bullets per section.
- Lead with the capture point and recommended route.
- Do not produce a full business model report unless the user explicitly asks.

## When to use

Use this skill when the user asks for:

- How to monetize, capture value, design pricing power, or avoid only doing delivery labor.
- Economic rent, Alpha/Beta, toll bridge, moat, value capture, competitive advantage, or business model strategy.
- A system for turning a strategic direction and key resources into durable capture.

This skill is the third stage of the strategy pipeline:

```text
DNS/opportunity -> Wardley/self-review -> rent/Alpha capture -> leverage/effectuation roadmap
```

If strategic direction and key resources are unclear, reconstruct them from context or ask before designing capture.

## Core workflow

1. **Confirm the direction and resource base.**
   - Direction: market, buyer, pain, category, and wedge.
   - Resources: capabilities, proof, distribution, relationships, data, product assets, capital, and reputation.
   - If missing, ask for the minimum facts needed; do not fabricate a capture system.

2. **Separate value creation from value capture.**
   - Value creation: what improves for the buyer or system.
   - Value capture: why money, attention, access, or status flows specifically to the user.
   - Use the formula: `return = created value x capture coefficient`.

3. **Identify Alpha.**
   - What does the user know, see, or do that the market has not priced correctly?
   - What wrong consensus, missing integration, timing mismatch, or neglected buyer pain can they correct?
   - Distinguish Alpha from Beta: using a hot tool or riding a broad trend is not enough.
   - Separate `personal Alpha` from `institutional Alpha`:
     - Personal Alpha can be tested, expressed, and captured through the user's own assets.
     - Institutional Alpha needs platform authority, brand, proprietary data, team delivery, industry credentials, or senior buyer trust.

4. **Run a capture-path check.**
   - If the capture path needs top-level authority, recommend borrowed leverage instead of fake personal monetization.
   - Choose one route:
     - Build personal asset: content, template, tool, diagnostic, benchmark, or case library.
     - Join stronger platform: employer or role that gives status, cases, data, and buyer access.
     - Partner with authority holder: domain expert, consultant, founder, investor, or operator with trust.
     - Defer: keep as long-term narrative, not current wedge.

5. **Choose rent types.**
   - Information rent: asymmetric expertise, diagnosis, data, evaluation, or judgment.
   - Reputation rent: trusted personal brand, proof, authority, or visible taste.
   - Interface rent: default entry point, workflow surface, API, marketplace, or distribution node.
   - Complementary-asset rent: channel, implementation capacity, support, integration, buyer access.
   - IP/license rent: protected method, content, software, copyright, patent, or reusable playbook.
   - Capital rent: patient capital or ability to absorb risk others cannot.
   - Relationship or license rent: use carefully; flag ethical or dependency risk.

6. **Design the capture architecture.**
   - Offer: what the buyer buys.
   - Buyer: who controls budget and why now.
   - Capture point: where value cannot bypass the user.
   - Proof asset: case, benchmark, tool, dataset, public artifact, or referral.
   - Distribution: how demand repeatedly reaches the user.
   - Pricing: how price maps to outcome, urgency, or avoided loss.
   - Compounding loop: how each delivery increases future capture.

7. **Check good rent vs bad rent.**
   - Good rent: temporary excess return from innovation, skill, better design, or real problem solving.
   - Bad rent: extractive dependence on closed access, artificial lock-in, or fragile politics.
   - Prefer capture systems where the bridge can be challenged by new bridges.

## Questions to ask

Ask only what changes the capture design:

- What strategic direction has already been chosen?
- What buyer would be worse off if you disappeared from the system?
- What do you know or control that competitors cannot copy within weeks?
- Where can you sit in the value chain so the value flow cannot easily bypass you?
- What proof asset can make the buyer trust the capture point?
- Which rent type is realistic now: information, reputation, interface, complementary asset, IP, capital, relationship, or license?
- What would make this capture system extractive, fragile, or ethically wrong?
- Is this Alpha personally capturable now, or institutional and therefore dependent on borrowed leverage?
- If the direct capture path is weak, should the user build a personal asset, join a stronger platform, partner with an authority holder, or defer?

## Failure modes / avoid

- Do not equate value creation with value capture.
- Do not claim Alpha when the user is only following a broad market Beta.
- Do not confuse institutional Alpha with personally capturable Alpha.
- Do not design a moat before naming the buyer and capture point.
- Do not recommend personal monetization when the capture path actually requires platform/status/relationship leverage.
- Do not recommend platform lock-in or artificial scarcity as the default.
- Do not ignore proof assets; capture without proof becomes wishful positioning.
