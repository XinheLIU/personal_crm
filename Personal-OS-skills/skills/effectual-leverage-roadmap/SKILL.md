# Effectual Leverage Roadmap

> Last updated: 2026-05-30

## Output style

- Default to short Markdown: 2-4 sections, one compact table when useful, 3-5 bullets per section.
- Lead with the route and next action.
- Keep roadmaps operational; avoid long motivational framing.

## When to use

Use this skill when the user asks for:

- An action plan, roadmap, next steps, 30/60/90-day plan, or tactical design.
- Effectuation, leverage, affordable loss, resource-first experimentation, or how to act under uncertainty.
- Revising previous thinking after a strategic direction has been chosen.

This skill is the fourth stage of the strategy pipeline:

```text
DNS/opportunity -> Wardley/self-review -> rent/Alpha capture -> leverage/effectuation roadmap
```

If direction is unclear, use `dns-opportunity-planning` first. If capture is unclear, use `value-capture-rent-alpha` first or reconstruct the missing capture assumptions explicitly.

## Core workflow

1. **State the strategic direction.**
   - Name the chosen direction, buyer/user, wedge, and intended value-capture point.
   - If the plan is revising prior thinking, state what changed and why.

2. **Inventory bird-in-hand resources.**
   - Who the user is: identity, taste, credibility, constraints.
   - What the user knows: skills, tacit knowledge, methods, data, tools.
   - Who the user knows: potential buyers, partners, reviewers, referrers, collaborators.

3. **Set affordable loss.**
   - Define acceptable loss in time, money, reputation, relationship capital, and opportunity cost.
   - Design actions so downside is bounded and upside remains open.

4. **Choose the leverage route.**
   - Personal fast loop: 30-day low-cost experiments that produce market signal and owned assets.
   - Platform/status leverage: job, company, role, or institutional context chosen to borrow authority, cases, data, team, and buyer access.
   - Relationship leverage: partner, interview, referral, or co-creation loop with people who own domain trust or distribution.
   - Content/IP leverage: public or private memo, diagnostic, template, benchmark, or tool that packages judgment.
   - Deferral: when the direction is valid but cannot close yet.

5. **Choose leverage type.**
   - Labor leverage: team/process coordination.
   - Machine/tool leverage: automation or production capacity.
   - Infrastructure leverage: reusable shared system with low marginal cost.
   - IP/content/software leverage: method, code, template, article, course, benchmark, or playbook.
   - Network/platform leverage: user-generated supply/demand, marketplace, standard, community.
   - Debt/financial leverage: only when judgment and cash-flow resilience are clear.

6. **Design the experiment sequence.**
   - Each experiment should produce information or an asset.
   - Prefer tests that can change the next step: interview, public post, prototype, demo, paid pilot, benchmark, referral ask, or partner proposal.
   - Use Crazy Quilt: seek commitments from partners before overbuilding.
   - Use Lemonade: treat unexpected response as a signal for reframing.
   - If the route is platform/status leverage, design company/role selection criteria and learning/case extraction goals.

7. **Create decision checkpoints.**
   - Continue, pivot, pause, or kill based on observable signals.
   - Update previous assumptions explicitly after each checkpoint.
   - Name what evidence would trigger switching from personal fast loop to platform/status leverage, relationship leverage, content/IP leverage, or deferral.

## Questions to ask

Ask only when needed to make the roadmap executable:

- What direction has been selected, and what is the current capture hypothesis?
- What can you spend in the next 30 days without regret?
- Which three people can give real signal, not politeness?
- What can be shipped in one week that creates a public or reusable asset?
- What would count as a partner commitment?
- Which leverage type should this plan compound toward?
- What previous belief should be updated if the first experiment fails?
- Which route is realistic now: personal fast loop, platform/status leverage, relationship leverage, content/IP leverage, or deferral?
- What evidence would prove this route cannot close and should be switched?

## Failure modes / avoid

- Do not create a roadmap that starts with building a large product before demand or partner signal.
- Do not optimize for expected return when uncertainty is high; optimize for affordable loss and learning.
- Do not use "research more" as a step unless it has a concrete artifact and decision use.
- Do not choose debt or heavy fixed-cost leverage before the value-capture system is proven.
- Do not let tactics drift away from the selected strategic direction.
- Do not force a personal fast loop when the real requirement is platform/status/relationship leverage.
- Do not recommend job moves generically; tie platform/status leverage to specific case, data, authority, reputation, or buyer-access gaps.
